데이터베이스 트랜잭션의 `COMMIT` 성공은 ACID의 지속성(Durability)에 따라 변경 사항이 영구 반영되었음을 의미한다. 그러나 분산 복제 구조나 스토리지 계층의 성능 최적화로 인해 지속성 보장이 깨질 수 있으며, 동시성 제어와 격리성(Isolation)이 충분하지 않은 경우에도 커밋된 변경 사항이 논리적으로 손실될 수 있다.

## 1. 비동기 복제(Asynchronous Replication)와 장애 조치

- **복제 지연 구간(Replication Lag)**: Primary 노드가 로컬에 트랜잭션을 커밋하고 클라이언트에 성공 응답을 반환한 직후, 변경 로그가 Replica 노드로 전달되기 전에 Primary 장애나 네트워크 격리가 발생할 수 있다.
- **승격 및 로그 폐기**: 복제가 완료되지 않은 Replica가 새 Primary로 승격(Failover)되면 기존 Primary에만 커밋되었던 내역은 클러스터 관점에서 유실되며, 추후 기존 Primary가 재합류할 때도 새 Primary와 분기된 미복제 로그는 폐기(Discard)된다.

## 2. 디스크 플러시(`fsync`) 지연 및 휘발성 캐시

- **로그 동기화 완화 설정**: 쓰기 처리량(Throughput)을 높이기 위해 커밋 시점에 디스크 물리 기록(`fsync`) 완료를 대기하지 않고, 데이터베이스 내부 로그 버퍼나 OS 페이지 캐시에만 기록한 뒤 성공 응답을 반환하는 경우 발생한다.
- **프로세스·OS 장애 및 전원 차단**: 로그가 비휘발성 매체로 플러시되기 전 데이터베이스 프로세스 비정상 종료(내부 버퍼 유실), OS 커널 패닉, 전원 차단(OS 페이지 캐시 유실)이 발생하면 커밋된 트랜잭션 로그가 휘발성 메모리와 함께 소실된다.
- **하드웨어 쓰기 캐시**: 데이터베이스와 OS가 `fsync`를 통해 디스크 캐시 플러시 명령을 전달하더라도, 배터리 백업(BBU)이나 전력 손실 보호(PLP)가 없는 스토리지 컨트롤러·디스크가 플러시 명령을 무시하고 휘발성 쓰기 캐시(Write-back Cache) 단계에서 완료 응답을 반환하면 전원 차단 시 동일한 손실이 발생한다.

## 3. 동시성 제어 부재로 인한 갱신 손실(Lost Update)

- **격리성 결함과 경합**: 지속성이 아닌 격리성(Isolation) 영역의 문제로, 두 트랜잭션이 동시에 동일한 데이터를 읽어 수정·반영(Read-Modify-Write)하는 과정에서 약한 격리 수준으로 동작하고 비관적 잠금, 낙관적 잠금(버전 검증), 원자적 쓰기 연산 등의 동시성 제어가 적용되지 않은 경우 발생한다.
- **논리적 덮어쓰기**: 먼저 커밋된 트랜잭션은 정상 종료되었으나, 동시에 실행 중이던 다른 트랜잭션이 이전 상태를 기준으로 데이터를 덮어쓰고 커밋하면서 첫 번째 커밋의 변경 사항이 논리적으로 손실된다.
